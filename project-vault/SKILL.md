# project-vault · 项目知识库架构 Skill

> 版本 v2.0 ｜ 建立 2026-10-19 ｜ 蒸馏自真实运转的项目库与公司级多仓库库。
> 本文写给执行初始化、日常维护以及评审本 Skill 的 AI：规则与脚本必须一起核对，不能只改说明不改行为。

## 0. 这是什么，解决什么问题

一套**项目知识库生成器＋运行规范＋防腐工具**。核心矛盾是：AI 没有跨会话记忆，而项目会运行数月，事实、决定、口径、开放问题必须落盘，并且经得起持续累加。

适用：单人或小团队、需要 AI 长期陪跑的项目（需求、方案、合规、外部对接、推进、文档＋代码混合）。不适用：纯代码仓库、一次性短任务。公司级多项目演进见 [references/架构演进.md](references/架构演进.md)。

本 Skill 做四件事：生成结构、立下 AI 规则、提供可执行校验与归档、可选生成**真实可运行**的代码骨架。

## 1. 五条宪法

1. **文件是唯一记忆**：没落盘＝不存在。用户确认的事实/决定/口径默认写入归口，不回问“要不要记”。
2. **先读后写、唯一归口**：新信息并入旧文件；推翻旧结论就改旧结论，不建碎片文件、不追加矛盾补丁。
3. **编号注册表**：Q/R/E/D/F 各有归口，从 `REGISTRY.md` 取号，不复用、不跳号；跨文件引用编号而不复制全文。
4. **入口分层**：`AGENTS.md`（规则）→ `STATUS.md`（当前状态）→ `00_项目主页.md`（地图）→ 归口文件。新会话读 3～5 个文件即可开工，不反问背景。
5. **机械防腐**：状态滚动重写，日志归档，工程接续与历史分离；新增/移动文件后跑体检，不能仅靠 AI 自觉。

## 2. 关键架构决策

### 2.1 规则、状态、日志分职

| 文件 | 内容 | 更新方式 | 防腐 |
|---|---|---|---|
| `AGENTS.md` | 规则、角色、材料流水线 | 仅规则变化时改 | 禁止追加状态或日志 |
| `STATUS.md` | 当前阶段、焦点、最近决策、阅读指针 | 滚动重写 | 永远一屏 |
| `CHANGELOG.md` | 实质变更＋操作人 | 追加 | 超 50 条归档 |
| `REGISTRY.md` | Q/R/E/D/F 上界与归口路径 | 取号时同步 | 唯一编号来源 |
| `vault.conf` | `BRANCH_MODE=single|dual` | 分支策略变化时改 | 唯一分支配置 |

状态历史看 CHANGELOG，文件历史看 git。工程 `进度记录.md` 同样分为滚动的“新会话接续提示”和追加日志；大段测试/部署输出只留摘要与制品指针，不得把进度文件当终端转储。

### 2.2 位置无关与标准链接

- 库内互链只用相对 Markdown 链接，不用 `[[wikilink]]`，不写 `/Users/...`、`D:\...` 等绝对路径。
- 路径含中文、空格必须可用；URL 编码空格和 `<含空格路径>` 形式由校验脚本处理。
- `.obsidian/`、`.workbuddy/` 是工具本地状态，默认忽略。

### 2.3 双层 git：知识库与代码库各录各的

```text
<项目文件夹>/                 ← 知识库 git A
├── .git/
├── AGENTS.md / STATUS.md / REGISTRY.md / vault.conf
└── <代码库目录>/              ← 独立 git B，被 A 的 .gitignore 整行排除
    ├── .git/
    ├── AGENTS.md             ← 工程规则，优先级在本目录更具体
    └── 进度记录.md
```

外层排除代码目录是为了避免 gitlink/submodule 纠缠。知识库 STATUS 只写工程摘要＋指针；commit、测试、部署实况留代码库。活跃、历史、参考仓必须在项目主页标明用途，历史代码与 bundle 不复制进文档库。

代码骨架是可选模块，结构见 [references/代码库结构.md](references/代码库结构.md)。主体保持技术栈无关；示例栈可替换，但生成的命令必须真实存在。

### 2.4 分支、快照、发布分离

- `single`：main 是日常工作分支，适合纯本地或简流程。
- `dual`：main 是已发布真相，`feat/next` 是唯一编辑工作区；main 不直接开发。
- 初始化 `--git` 默认 dual，也可 `--branch single`。已有库升级时不擅自改分支模式。
- **快照**＝先体检再保存工作区，默认不推送；**发布**＝显式确认后 dual 的 feat/next 合入 main 并同步远端；**代码部署**由代码仓自己的流程负责，三者不得混为一谈。
- AI 不自行 commit/push/snapshot/publish，必须由用户明确要求。禁止强推或用 reset/clean 清掉校验障碍。

### 2.5 敏感信息分层

库内只存字段结构、提供状态、证据和存放指针。真实值只放 git 忽略的 `本地信息/` 或用户认可的受控渠道。AI 对本地信息只通过 `scripts/private.sh` 的遮蔽接口操作，值由用户本人填写，永不回显。pre-commit 扫描的是**暂存 blob**，不是工作区表面内容。

### 2.6 公司级与项目级分层

本生成器生成单项目库，不在初始化时替用户做公司级迁移。组织、制度、公司账号等跨项目内容只留指针。若演进为同库多项目，每个项目必须保留独立 REGISTRY 和编号作用域；详细结构与升级门禁见 [references/架构演进.md](references/架构演进.md)。

### 2.7 脚本是加速器，不是第二事实来源

日常脚本在 macOS/Linux/git-bash 运行。取号、链接、编号、归档均有手工等价步骤；脚本不可用时能力仍存在。私密信息例外：无安全脚本时由用户本人编辑，AI 不直接读取秘密原文。`selftest.sh` 只用于 Skill 自身回归，不拷进生成的库。

## 3. 生成出来的库

```text
<项目文件夹>/
├── AGENTS.md / STATUS.md / CHANGELOG.md / REGISTRY.md
├── vault.conf                 ← single / dual 唯一配置
├── 说明.md / 00_项目主页.md / .gitignore
├── 10_需求/
│   ├── 原文/
│   ├── 白话全解.md
│   └── 功能需求清单.md         ← F 类归口
├── 20_方案/
├── 30_合规与决策/              ← 主体、红线、D 类决策
├── 40_推进/                    ← Q/R/E、信息提供状态
├── 90_模板/                    ← 决策/问题/纪要/信息块/文件头尾
├── 99_附件/清单.md + 历史/
├── 本地信息/                   ← 本地生成、git 忽略，真实值由用户填写
└── scripts/
    ├── next-id.sh / check-links.sh / check-registry.sh
    ├── archive-changelog.sh / doctor.sh
    ├── pre-commit.sh / install-hooks.sh
    └── snapshot.sh / publish.sh / private.sh

（可选）<代码库目录>/            ← 可运行的分层 monorepo，独立 git，另有 archive-progress.sh
```

## 4. 初始化流程

**Step 0 · 确认目标**：默认当前目录。若目标非空（除 `.DS_Store`），列出将新增内容并请用户确认；同名文件跳过不覆盖并报告。不得把测试库初始化在 Skill 自身目录内。

**Step 1 · 一次问齐**：
1. 项目名称；2. 一句话简介；3. 是否启用 git（建议）；4. 启用 git 时选 single 或 dual（建议 dual）；5. 是否生成代码骨架及目录名（如 `backend`，可选）。

**Step 2 · 生成**：

```bash
bash scripts/init-vault.sh <目标目录> <项目名> ["简介"] \
  [--git] [--branch single|dual] [--code <目录名>]
```

脚本会复制模板、替换 `{{PROJECT_NAME}}`/`{{PROJECT_DESC}}`/`{{DATE}}`/`{{VAULT_VERSION}}`、创建空目录和本地信息目录、拷贝日常脚本、可选生成代码骨架与双层 git。`--code` 只接受单层目录名，拒绝绝对路径、斜杠和 `..`。git 首次提交失败必须报告失败，不能伪报成功。

无 bash 时手工复制 `templates/`（`_code/` 仅选代码骨架时使用），`.tmpl` 去后缀并替换上述四个占位符，普通文件原样复制；创建 `10_需求/原文/`、`20_方案/`、`99_附件/历史/`、`本地信息/`。启用 git 则初始化 main、先跑体检再首次提交、安装 pre-commit shim，并按 `vault.conf` 建分支。代码仓独立 git，外层忽略代码目录。

**Step 3 · 自检**：运行 `bash scripts/doctor.sh`，错误为零；首次会话的角色待补项属于警告，需主动问齐。

**Step 4 · 教用户开口**：库建好后，新会话打开文件夹说“读 AGENTS.md，我开始发材料了”。代码、公司级资料、历史仓只登记指针与用途，不复制事实。

## 5. 日常运作

### 5.0 材料录入流水线

① 原件入 `99_附件/` 并登记（敏感原件只留本地）→ ② 解读续写白话全解 → ③ 新发现取号进 Q/R/E/D/F → ④ 修订全局线 → ⑤ 同步项目主页 → ⑥ 滚动更新 STATUS → ⑦ CHANGELOG 追加一行（含操作人）。

### 5.1 取号

`bash scripts/next-id.sh Q` 输出 Q1 并同步上界；带原子锁。手工等价：读上界 → 加一 → 写回 → 同一轮在归口文件使用。F 类归口固定为 `10_需求/功能需求清单.md`。

### 5.2 链接与编号校验

- `bash scripts/check-links.sh`：检查相对链接，剥离代码示例，剪枝嵌套代码仓；wikilink 和绝对路径按规则报告。
- `bash scripts/check-registry.sh`：上界小于实际最大＝错误；引用未登记＝错误；登记但归口外无引用＝警告。
- 手工等价：剥离代码示例后提取链接/编号，逐项核对目标、归口与上界。新增、改名、移动文件后必跑。

### 5.3 写文件的固定动作

维护顶部更新日期；文件增删移动同步主页；实质改动写 CHANGELOG；不在单文件末尾再写一份变更史。问题条目可保留“旧句＋更正时间戳”作为问题演进史，但当前事实归口必须改成当前结论。

### 5.4 日志归档

- 知识库：`bash scripts/archive-changelog.sh [50]`，保留固定头与最新条目，旧段移入 `99_附件/历史/`。
- 代码库：`bash scripts/archive-progress.sh [50]`，只归档标记区内日志，顶部接续提示不动。
- 手工等价：保留固定头与最新 N 条，将最旧条目移入对应历史文件；不得按任意行号切断多行条目。

### 5.5 私密信息

`private.sh view/add/insert/rename/rm` 只处理 `本地信息/` 内普通文件；view 遮蔽所有非空值，add/insert 只创建空标签。禁止路径逃逸、直接读取原文、把值放命令行或写进日志。信息是否已提供看 `40_推进/信息提供状态.md`，不看库内是否有真实值。

### 5.6 快照与发布

- Git 克隆不会复制钩子；新克隆先运行 `bash scripts/install-hooks.sh`。已有自定义钩子不会被覆盖，快照/发布检测到门禁未安装会停止。
- `bash scripts/snapshot.sh [--push]`：先 doctor，后提交；dual 只允许 feat/next。`--push` 仍需用户明确要求，执行后校验远端一致。
- `PROJECT_VAULT_PUBLISH_CONFIRM=1 bash scripts/publish.sh`：仅 dual、feat/next、干净工作区、origin 完整时运行；校验→fetch→合并 main→推送→回合同步 feat/next→再校验。
- 无 bash 时不建议手工自动发布；按架构文档逐步核对分支、工作区、远端和合并结果，任一步失败即停并报告。

### 5.7 会话收尾与体检

① 口头结论落盘 → ② 重写 STATUS → ③ 追加 CHANGELOG → ④ `bash scripts/doctor.sh`。doctor 统一跑双校验，并检查必备文件、敏感文件跟踪、嵌套仓忽略、钩子与日志肥胖；错误必须处理，警告必须说明。

### 5.8 项目终态

STATUS 改为“已完结＋日期＋结局＋关键结论指针”；CHANGELOG 记录完结；用户明确要求后再打 tag；AGENTS 开场标注只读；库可归档但不删除，作为后来项目的判例。

### 5.9 自动快照（可选）

定时任务属宿主 AI 工具，不随 Skill 复制；一库只能有一个调度属主，换工具先撤旧装新。自动任务只能快照当前工作分支，不能发布、推送或改 main；若项目要求所有快照都需口令，则不要使用无人值守任务。

## 6. 编号系统

| 前缀 | 含义 | 归口 |
|---|---|---|
| Q | 开放问题/待决策 | `40_推进/待确认问题清单.md` |
| R | 风险 | `40_推进/待办与风险.md` |
| E | 外部依赖/对接方 | `40_推进/依赖与对接清单.md` |
| D | 已拍板决策 | `30_合规与决策/决策记录.md` |
| F | 功能需求 | `10_需求/功能需求清单.md` |

同一事项不建两个编号。历史库已有 D-01、BRD 原编号等格式时，升级必须先做兼容或单独迁移，不能直接用新格式“修数”。

## 7. 模板与占位符约定

- 模板与目标结构一一对应；`templates/_code/` 只在 `--code` 时使用。
- 占位符只有 `{{PROJECT_NAME}}`、`{{PROJECT_DESC}}`、`{{DATE}}`、`{{VAULT_VERSION}}`；版本在 init 脚本单点维护。
- 用户输入进入 sed replacement 前一律 `esc()`；新增占位符同步更新手工流程和自测。新增文件不得含真实项目名、绝对路径或秘密值。
- 修改脚本、模板或生成格式后，必须升版本、更新文档并跑完整 selftest。

## 8. 明确不做的事

- 不把任何具体业务、项目口令、部署流程或技术偏好写进通用主体；真实项目名只允许存在于历史变更记录。
- 不在初始化时自动做公司级多项目迁移、旧库覆盖升级或 wikilink/D-01 强制转换。
- 不配置真实 git 远端，不自动推送，不迁移老代码，不生成或读取真实秘密。
- 不让代码骨架宣传不存在的命令，不用占位测试冒充端到端验收，不为“通过”而降低测试或安全门禁。
